# Project Quality Standards

These standards describe how projects are presented in this portfolio. They are intended to keep descriptions useful, reproducible, and honest.

## 1. Project descriptions

Every featured project should explain:

- The problem or purpose.
- The intended users or context.
- The implemented features.
- The technologies actually used.
- The current development or research stage.
- A direct link to its source repository.

Avoid claiming features that are only planned.

## 2. Screenshots and visual evidence

- Use screenshots captured from the real running application.
- Identify the relevant page or feature in captions.
- Do not present concept art as a product screenshot.
- Do not include private records, credentials, tokens, or personal information.
- Prefer a small number of clear, high-resolution captures over decorative filler.

This portfolio may use project illustrations and source photographs when their role is explicitly described.

## 3. Technical claims

- Publish performance metrics only when the experiment and evaluation method are documented.
- For machine-learning projects, identify the dataset, split, evaluation metrics, and limitations.
- Do not claim model accuracy before training and evaluation have actually been completed.
- Distinguish implemented features from experiments and future plans.

## 4. Repository readiness

A project README should ideally include:

- Purpose and feature summary.
- Prerequisites and installation steps.
- Configuration instructions using safe example values.
- Run and test commands.
- Screenshots or a short demonstration when available.
- Known limitations and contribution guidance.

## 5. Maintenance

Review links, installation steps, dependencies, and screenshots when a project changes significantly. Keep the profile catalogue aligned with the actual repositories.
